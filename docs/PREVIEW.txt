PNGTUBER MAX by Clatasha — 0.1.17 DEVELOPMENT PREVIEW

Extract the complete folder and open PNGTuberMax.exe. Keep the resources and DLLs together.
Requires Windows 10/11 x64 with .NET Framework 4.8. No OBS or another PNGTuber app is needed.
This product includes software developed by Rahisaurus. This is a modified RahiTuber-based app.

BLUE MAX DESIGN
New Inter typography, raised controls with shadows and edge highlights, a branded header,
blue panels, and 30 original action icons. Hover controls to see their descriptions.
The inherited sprite manager, motion/physics, talking/blinking states and shortcuts remain.
Use Make Portable to move an existing XML character setup with its referenced PNG assets.
Your private DERSPAWN artwork is not shipped in this application.

VIRTUAL CAMERA — EXPERIMENTAL DIRECTSHOW BACKEND
Click Camera setup once and approve the Windows administrator request.
Setup runs without a visible PowerShell window and shows its result in Camera Preferences.
Restart the receiving app and select PNGTuber Max Camera. Press Start virtual camera.
The camera sends the avatar scene only, with an opaque navy background and aspect-preserving
letterboxing at 640x480 / 30 FPS. Editor controls, shadows and tooltips are excluded.
Camera output is off each launch; regular app use does not require elevation.
The camera source may not work with Media Foundation-only receiving apps.
Do not use two instances to publish the same camera. Another instance remains usable for editing.

Close the receiving app before removing/updating the camera component.
To remove it, run Uninstall-Camera.ps1 as administrator. Saved characters remain.

PNG RIG AND LIVE FACE
PNG bone rigs, rig-following accessories, local face tracking and eye/mouth sublayers
are available. See RIGGING.md for setup and precise contour editing.

VALIDATION
The automated Windows build checks layout, audio-meter thresholds and the frame contract.
It also registers the camera and tests real DirectShow frame delivery with a simulated publisher.
Compilation does not establish webcam compatibility or the visual appearance on your machine.
Receiving-app and Windows visual tests are required before using this preview for a live stream.

0.1.2 CHANGES
The editor is split into left studio/layers, middle avatar preview, and right Preferences.
Preferences remain visible; choose a settings section using the selector at the top.
Imports/open/save use Windows file dialogs. Ctrl+Open merges into the current project.
Below the microphone selector, six blocks continuously display the raw selected-input peak.
Four green blocks, one amber, and one red cover quiet speech through levels near clipping.
The meter stays visible when advanced audio controls are collapsed.
Layer additions/duplicates are queued safely between UI frames; blank sprites cannot crash
selection-guide drawing. Folder copying uses stable identifiers while the list grows.
Camera setup repairs both Windows camera registrations, unblocks downloaded camera DLLs,
and records warnings separately from errors. Its result appears in Camera Preferences.
Use Check camera delivery to test registration and real DirectShow frame delivery.
If setup or checking fails, send the error text from the panel or camera-report.txt /
camera-install-log.txt in %LOCALAPPDATA%\Clatasha\PNGTuberMax.

0.1.3 AUDIO AND PLUSH PNG MODE
Missing audio never opens a modal or prevents editing. Choose an input, refresh, or use the
inline Use system default button. Failed devices show an error beside the input controls.
Device selection uses actual PortAudio IDs, and refresh closes the old stream safely.

Expand a body layer and open Plush PNG mode. Idle is the front image; import the Back view
PNG through its image button. Enable Join front and back PNGs, then adjust Roundness / Turn.
Front and Back buttons reset the view; Follow mouse turn gives live left/right movement.
Both surfaces share silhouette seams, including at side views. No skeleton or model is needed.
Use matching transparent canvases and similarly shaped front/back artwork for best results.
The back image and settings save with the project and are included by Make Portable.
Talking/blinking front sprites continue to work. Camera output includes the plush effect.
This first version wraps the body surfaces. Eye/accessory layers retain existing attachments;
curved surface attachment and face tracking remain planned. Fine contours and strong side
turns need testing with your mascot artwork. Rendering uses a bounded sprite tessellation.

0.1.4 ROTATION, EDITOR AND SAVE FIXES
Alt + left drag inside the avatar preview turns the most recently selected plush body.
Click the body's layer header to select it; if none is selected, the first visible plush body
is used. Release Alt/mouse or leave app focus to end the drag. Manual turning switches off
mouse-follow so the angle stays where you leave it. The angle saves with the project.
Visible surfaces are clipped to their actual facing range, avoiding folded overlapping strips.
Rear texture coordinates remain fractional when front/back image dimensions differ. Smooth
static PNGs also use mipmaps on supported GPUs to reduce aliasing during compressed turns.
Sprite inputs are stacked vertically. Blink has an explicit enable checkbox and its own image
picker; TalkBlink appears when blinking while talking is enabled. The editor has scrollbars
for smaller windows; phoneme and audio options fit the left column.
Toolbar buttons include both icon and label in one clickable area. Save opens Save As for an
unnamed project. Ctrl+S saves; Ctrl+Shift+S opens Save As. A successful write shows Saved: name.

0.1.5 EDITOR SPACE AND SHARP PLUSH SAMPLING
The studio returns to the original RahiTuber sprite/phoneme layout with a 720-pixel default
working width. The avatar preview takes the smaller middle column. Transform fields reserve
only the actual label width, leaving room to see and edit X/Y values.
Plush surfaces use continuous per-pixel inverse projection instead of triangle-strip texture
interpolation. Output is cached at the body's rendered resolution. No source mipmaps are
created, and the plush preview bypasses the extra FXAA blur pass. Premultiplied alpha is
composited once in the plush preview, preserving translucent outline colours.
The standard sprite renderer retains its existing appearance preferences. Tests cover detailed
striped PNGs at 2 and 5 degrees, neutral-view detail/alpha, side seams and XML save/overwrite.

0.1.5 CAMERA NEGOTIATION
Native format queries now allocate caller-owned COM buffers and validate output pointers.
Windows tests cover device selection and receiver stop/restart, in addition to frame delivery.
Close all receiving apps and click Install / repair camera once to replace the old DLL.
The exact recording app reported to crash has not yet been identified or verified.

0.1.6 CAMERA UPDATE AND DIAGNOSTIC CORRECTIONS
Camera updates use a separate build directory so an old, loaded DLL cannot block replacement.
Fully close and reopen receiving apps after setup; they may still hold the previous build.
The checker verifies installed and packaged DLL hashes before testing delivery.
Internal delivery success does not prove OBS or Mirillis Action compatibility.
Native tests now bind through the device moniker, following the OBS discovery path.
Setup retires the obsolete Clatasha Camera (Preview) device entry from our first prototype.
It keeps that prototype's files and COM class; no character assets are removed.

0.1.7 NATIVE CAMERA BACKEND
The receiving app now loads a native C++ DirectShow source built on Microsoft base classes.
Both 32-bit and 64-bit DLLs are included; camera registration no longer uses RegAsm/CLR.
The standalone diagnostic still uses .NET, outside the receiving app.
RGB32 and RGB24 output formats are available at 640x480 / 30 FPS.
The camera migration removes our previous managed loader registration.
Close and restart all camera receivers after installing this build.
Compatibility with the user's OBS and Mirillis Action installation requires retesting.

0.1.8 CAMERA CONTROL VISIBILITY
Start camera is green; Stop camera is red, in both the studio toolbar and Camera preferences.
The buttons are taller and an OUTPUT ON/OFF label states whether the avatar is being sent.
When output is off, a short instruction points to the green Start camera button.
The native camera implementation remains 0.1.7.

0.1.9 PNG RIG AND LOCAL FACE TRACKING
Editable PNG bones, mesh deformation, rig-following accessories and live eye/mouth sublayers. Bundled local tracking runtime; named webcam selector, neutral calibration and smoothing. See RIGGING.md for setup and preview limitations.

0.1.10 CONTINUOUS SURFACE AND FACIAL CROP EDITOR
Replaces per-row silhouette shaping with a connected PNG depth surface, GPU depth testing and supersampled edges. Thin antenna details receive shallow depth. Live eyes and mouth are composited into the front surface before turning and bending. Each feature has a large live crop editor, zoom/pan, independent crop width/height and rotation, three mask shapes, softness and brightness/gamma/colour adjustments. Placement and all settings save with the project. Requires the bundled tracker folder from 0.1.9; update both the application and tracker.py together.

0.1.11 TRANSPARENCY AND CROP COPYING
Transparency preserves normal window styles, title-bar direction and interactive mouse input. Disabling restores DWM margins and blur state. Each facial crop editor has Copy settings to and Copy settings at the bottom, copying all crop/mask/lighting settings while retaining destination avatar placement. PNG stitching is unchanged.

0.1.12 PRECISE EYELID AND LIP CUTOUTS
Tracked contours follow eye opening/closing and outer lips, retaining the mouth interior. Crop editor: Use precise eyelid / lip mask, contour padding/feather, boundary preview and mask offset/width/height corrections. Existing crops and lighting stay saved; Copy settings includes contour controls. Replace both PNGTuberMax.exe and tracker/tracker.py. Stitching and transparency handling are unchanged.

0.1.13 LOCKED ACCESSORIES AND RENAME EDITOR
Attachment > Attach to locks accessories to the parent transform, plush surface and PNG rig, bypassing child movement/physics. Bindings save with the project and parent visibility is inherited. Front attachments hide at rear-facing turns. Rename Layer has a full-width mouse Save button, a larger scrollable editor and a safe long-name buffer; Enter no longer closes it.

0.1.14 POPUP INPUT AND ENTER-TO-SAVE
The preview no longer removes focus from popups or floating UI on mouse-down. Rename/color, States, Portable and other overlapping dialogs retain their input. Avatar rig/turn/window drags yield to UI input. Enter-to-save is restored in Rename Layer alongside the mouse Save button.

0.1.15 COMPACT STUDIO CONTROLS
Start/Stop camera (webcam tracking) and Start/Stop virtual camera are side by side on the main studio toolbar, followed by a compact Setup button. New/Open/Save/Save as share one compact row with inline icons; Portable/Reload/Layer/Folder/States share a second compact row. Camera selection and calibration remain in Webcam rig preferences.

0.1.16 PER-IMAGE EDGE BLENDING
Each sprite slot has Edges controls for exterior-outline feather and inward trim, including Idle/Talk/Blink and the individual phonemes in More Talk settings. Values default to zero, save per slot, and reset without altering source PNGs. Sharp interior detail and premultiplied alpha are preserved. Derived textures and frame distance fields are cached.

0.1.17 CAMERA-ASSISTED LIP SYNC
More Talk settings now includes Audio, Camera and Combined sources for the existing five mouth shapes. Enable Use Talk Sprite and Phoneme Detection on the mouth layer. Start the webcam, then optionally capture closed, tall/open, wide and rounded shapes in Mouth calibration. Shape smoothing prevents rapid switching; closed lips respond immediately. Mode, smoothing and calibration save per layer. Camera modes fall back to audio when tracking is lost; missing images fall back to Talk/Idle. The app and tracker.py must be updated together (RIG4 mouth measurement contract).
